# 电厂数智化求职与面试讲解卡

日期：2026-10-14。配套 [前沿技术与国产备用设计](INTERVIEW-TECH-ROADMAP-20261014.md)。口述稿供练习，请按自己实际参与和掌握程度调整；尚不能独立解释的代码先补学，不将AI辅助成果描述成全部独立手写。

## 一分钟开场

> 我围绕电厂燃料、设备和能效业务做了一套个人软件原型。后端主要用FastAPI、SQLAlchemy，前端用React和TypeScript。我重点打磨了几条能验证的业务链路：点检断网后重传不能重复建缺陷，库存并发变化不能被旧盘点覆盖，煤质数据要分清单位和基准，能效模型要经过时间留出评估，表现不好就降级。
>
> 项目当前用模拟场景验证，没有现场投运和实测节煤收益。下一步我希望把统一数据口径、配煤约束优化和带引用的规程助手接进这些流程，同时预留openGauss、昇腾和国产求解器的适配路径。我能结合代码讲现有实现，也能说明这些升级需要什么验证。

## 三个可以讲代码的案例

### 1. 离线点检：一次重试为什么会造成业务错误

**问题**：现场网络差，服务器可能已保存记录，手机却没收到响应。如果重试当新记录处理，会重复建缺陷、扣健康度。

**实现**：当前原型用任务与测点确定记录身份，数据库唯一约束兜底；核对账户和内容，相同重传返回原结果，不同内容返回409，提示核对。权限仍然检查。涉及共享设备状态的写入在事务内串行，并在等待锁后刷新对象。

**验证怎么讲**：指向 [重传测试](https://github.com/nizuowanzhenbang/equipment-inspection/blob/8047049bb3158959172edc5a7148dd5f35be4217/backend/tests/test_record_replay.py)，看相同重传只有一条记录、一张缺陷、一次健康扣分；冲突保留原值；别的账户不能冒领。这些是仓库既有用例，本轮未复跑。

**取舍**：这套身份适合每个任务测点只提交一条结果的流程。将来允许同一任务多次采样，要引入采样身份和修订规则，不能继续沿用旧唯一键。

### 2. 煤质输入：为什么单位统一还不够

**问题**：18 MJ/kg和18 kcal/kg差距很大；收到基ar、空气干燥基ad、干基d描述的是不同水分条件，数值不可混用。缺失和零值也不是一回事。

**实现**：沿既有库内口径保存热值，显式单位做换算；基准不匹配拒绝，不猜水分条件；关键缺项单独标记，非有限数拒绝；重评不抹掉运输异常与已处理记录。

**验证怎么讲**：结合 [煤质发布证据](../progress/evidence/2026-10-11-coal-quality-contract.md)，演示同一热值两种单位、错误基准、缺项与零值。项目设置的输入保护范围不能说成行业质量合格标准。

**价值**：模型或供应商评分依赖这些输入。先保证口径可追溯，才有资格谈后续智能分析。

### 3. 能效评估：我怎样避免模型看起来有效

**问题**：用训练数据给自己打分会高估效果；工况变化后，原模型可能失效。

**实现**：现有代码按时间顺序以前80%训练、后20%验证，比较训练集均值基线；检查输入和训练范围，保存输入、数据摘要和模型版本。当前项目策略要求至少24个有效样本、MAE不超过5 g/kWh，并相对基线改善超过10%；这是原型门槛，不是行业验收标准。

**关键边界**：当前推荐氧量仍由负荷经验公式确定，线性回归用于收益估算；通过预测评估不能证明调参具有因果收益。confidence字段也不是经过校准的统计概率。

**下一步**：先把可调变量、库存与运行约束写清，再比较可行方案；收益最终要通过匹配工况的测量验证。[算法固定源码](https://github.com/nizuowanzhenbang/coal-unit-efficiency/blob/39180dc6eed80b5d8392641e03f72f3c60fe6ae3/backend/app/algorithms/combustion_optimizer.py)

## 十分钟讲解路线

| 时间 | 讲什么 | 出示什么 |
|---|---|---|
| 0–1分钟 | 业务问题、个人原型定位与技术栈 | 项目总览和模块关系 |
| 1–4分钟 | 点检丢响应、重试、冲突、检修验收 | 已有 [设备演示说明](https://github.com/nizuowanzhenbang/equipment-inspection/blob/76d799c1fc781147ea6bbdeaff0ee57e8bc659db/docs/DEMO.md)，按固定版本预演 |
| 4–6分钟 | 煤质单位/基准、能效留出评估 | 一条异常输入和模型降级原因 |
| 6–8分钟 | 下一步前沿设计：RAG解释依据、预测看趋势、优化选方案 | 配套设计图和合成配煤算例，明确为设计 |
| 8–9分钟 | 国产备用如何替换、如何验证 | 主备选型表，展开数据库锁或推理适配之一 |
| 9–10分钟 | 局限、个人贡献和下一步验收 | 固定提交、PR状态、尚未验证项 |

## 面试官常见追问

**“这为什么叫数智化？”**

台账和报表是数字化，流程之间可靠流转是协同，模型在评估后提供建议是智能辅助。更高一层是共同约束下做方案比较，再记录执行效果修正策略。我的现状主要是前两层和部分智能辅助，联合优化和持续反馈是下一步。

**“为什么不用大模型直接算煤耗、配煤？”**

大模型适合查规程和组织解释；数值计算交给可测试的公式、模型和求解器。配煤先检查库存、单位、热值与约束，再给出可行方案。语言流畅不代表物理和经济条件满足。

**“RAG比直接把文档塞进提示词强在哪？”**

可以按版本和权限检索少量相关片段，控制成本并定位依据。关键词适合设备编号和术语，向量适合语义匹配，重排提高候选相关性。还要用评估集检查漏召回、错误引用和无依据问题，不能只看几个好看的回答。

**“前沿模型有什么原理，你真接过吗？”**

我目前研究的候选包括时序基础模型和检索增强。时序模型把历史序列分块，结合变量关系预测未来；它是否适合电厂数据，要和简单基线做时间滚动回测。本项目尚未接入TimesFM-3，也未做现场验证；现有可展示的是简单模型的留出评估与降级。

**“有模型预测了，为什么还要优化器？”**

预测告诉我可能的趋势，优化器在库存、热值、成本等明确约束下选择方案。预测器不天然是可靠的调参响应模型，因此先做可解释的离线配煤，再研究燃烧响应与工况边界。

**“能证明节省多少钱吗？”**

目前只能展示模拟估算。比如600 MW连续24小时、假设供电煤耗降低1 g/kWh，对应14.4吨标准煤；再乘标准煤单价得到假设金额。这依赖出力、时间、煤耗口径等条件，不能当作本项目实测收益。热值不同的煤，也不能只比吨价。

**“你的设备失效概率准确吗？”**

现有设备模块主要是规则风险排序。没有明确故障标签、预测窗口和校准证据，我不会把分数称为可信失效概率。未来要报告漏报、单位时间误报和提前量，评估标签缺失与检修干扰。

**“多加重试就能保证跨系统可靠了吗？”**

不够。业务和待发消息要同事务，接收方要原子防重，回执要核对身份，内容冲突要可见，重启后要能恢复。设备PR #15和安全PR #4是这套设计的待合并候选，本轮核对仍open；不能讲成已全部发布，也不承诺跨库恰好一次。

**“国产化是不是换一个数据库地址？”**

数据库要验证驱动、SQLAlchemy方言、迁移、数据类型、唯一约束、锁和恢复；推理要验证模型、硬件、算子、量化和性能。统一接口能减少应用改动，不能省掉兼容验证。目前国产路线是设计备用，未宣称跑通或通过认证。

**“国产方案会比主方案差吗？”**

不能按来源判断效果。主方案本来也可以用Qwen等国产模型。选型比较同一业务评估集、可部署条件、资源成本和运维能力；主备时序模型不同，按相同误差指标验收，不要求参数量一样。

**“没有GPU怎么办？”**

先用现有CPU可运行的业务、规则、简单回归和小规模优化证明流程；知识助手可先做关键词检索与原文引用。没有在目标硬件测过，就不承诺大模型的吞吐和延迟。

**“为什么不先上强化学习和自动控制？”**

当前更缺统一数据语义、可信响应模型和执行反馈。先做能复核的离线决策与人工确认，等模拟环境、运行边界和效果证据具备，再讨论更复杂的策略。这是按现阶段证据安排投入。

**“这些代码是你自己写的吗，AI做了多少？”**

按真实情况回答：“我使用AI辅助梳理、编码和回归准备；我负责并能解释的部分是……，实际参与边界是……。”随后选一段自己能逐行讲清的事务或模型代码，解释失败路径和验证。不要把生成代码等同于已经掌握，也不要虚构独立开发经历。

## 按岗位调整重点

| 岗位 | 先讲 | 再展开 |

| 信息化/软件开发 | 离线重传、数据一致性、权限、迁移恢复 | 跨系统消息、国产数据库验证 |
| 生产技术/能效 | 煤质口径、能效计算与工况边界 | 约束优化、预测与实测收益区分 |

简历表述可用：“围绕电厂点检、煤质和能效场景构建并迭代个人软件原型，重点验证弱网重传、并发一致性、数据口径和模型评估；形成前沿智能辅助与国产备用架构设计。”请据实际贡献调整措辞。尚未实施的RAG、国产部署与联合优化不要列作已完成项目成果。

## 练习顺序

第一遍不看稿讲一分钟，第二遍围绕一个案例回答“为什么这样做、失败会怎样、怎么验证”，第三遍让对方连续追问国产兼容和模型边界。遇到答不上来的问题，把它变成下一项可验证工作。能画出输入到结果的一条链，解释关键代码和一个失败用例，比背技术名词更有说服力。
