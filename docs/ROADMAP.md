# 后续建设路线（未完成事项）

优先提升现有项目的可验证性，再考虑新增仓库。下列是下一轮开发候选，不代表已实现或后台自动执行。

| 优先级 | 任务 | 可验收结果 |
|---|---|---|
| P0 | 设备点检并发与离线重放幂等 | 同一任务记录重复请求只生成一次缺陷；并发测试通过 |
| P0 | 账户与配置加固 | 演示账户显式开关、生产启动配置校验、权限回归矩阵 |
| P0 | 盘点与库存一致性 | 覆盖盘点后新增出入库、并发出库、舍入差异的测试 |
| P1 | 数据库迁移与备份恢复 | 从旧版本升级及空库恢复均有可重跑验收脚本 |
| P1 | 接口契约和联动验证 | 点检→隐患/采购的模拟联动、超时和重试测试 |
| P1 | 前端按页面加载 | 衡量首次加载包体与路由切换；包含弱网/离线回归 |
| P1 | 依赖升级与安全扫描 | 分项目升级固定旧版本，验证兼容性，不以编译通过代替漏洞审计 |
| P2 | 信息化运维台账模块 | 仅在核心项目稳定后扩展 IT 资产、服务工单与变更记录 |

如果扩展信息化运维台账，应先复用现有设备/工单基础，明确 IT 资产与生产设备的边界；避免新增一个只有设计文档的仓库。
