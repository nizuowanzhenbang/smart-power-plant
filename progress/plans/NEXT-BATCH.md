# 下一批开工入口

范围：PP-030 设备采购/自动补货边界，及 PP-040 点检重大缺陷到安全隐患联动。两项仍待核查，不把路线图或旧分析当作实际缺陷/交付。沿 D-006，每次活动会话选择多个可独立验收单元，关键阶段保存，不为增加数量重做已交付内容。

1. 更新中央检出，运行 resume；同一远端 SHA 读五份核心/状态文件，报告当前认领、已完成和第一动作。若无活动认领，先 claim PP-030；若有其他执行者，核对原分支/PR 后按明确接管规则处理。
2. 核对 equipment-inspection 最新默认分支、现有 PR 与未提交改动；保留已验证的库存竞争、收货重放和盘点逻辑。只针对采购创建/更新、补货入口、数量金额与单号生成做实际读码/请求复现。
3. 将实际缺口拆成采购输入语义、自动补货边界、单号/请求竞争等可独立验收单元；不存在缺口则记录已有覆盖。确定小范围设计后逐项 RED→GREEN，保存完整远端代码 SHA 与下一动作。
4. 顺序切换 PP-040，先对照设备与安全两端实际路由/字段/身份/幂等约定及当前自动联动代码，明确对端宕机、响应丢失、重复/冲突和重启恢复的证据。设计依据真实契约，不预设已经有可靠消息机制。
5. 每个独立分支完整验收，保存真实 PR/CI/合并 SHA，再释放并更新 CURRENT/TASKS/SUMMARY/RELEASES。外部审查工具不可用时如实记录验证边界，继续能独立完成的检查。

远期 PP-050/060 数据语义与煤质到燃烧排放联合决策保留在队列；尚未启动。工厂现场、浏览器和数据库并发验收只在真实执行后声明。
