# Codex 电厂工作记忆规则

适用于本仓库及用户的电厂数智化工作。用户当前指令和实际代码、Git、PR 状态优先；历史规划中的授权描述不能扩大当前会话的授权。

## 开工前

1. 读取 smart-power-plant 默认分支最新 `progress/SUMMARY.md`、`progress/CURRENT.md`、`progress/TASKS.md`。按任务再读 `REPOSITORIES.md`、`DECISIONS.md`、相关日志与证据；不要每轮重读所有历史材料。
2. 记录本次读取的进度仓库提交 SHA。对当前任务核对目标仓库分支、HEAD、未提交改动及相关 PR；旧文档或本地缓存不能代替最新状态。
3. 用一段简短说明写出“已读进度 SHA、当前任务编号、已完成且不重做的内容、本轮第一项动作”。只有文档整理任务可直接从记录进入整理；代码任务仍需读实际源码。
4. 有实质工作时，先在 `CURRENT.md` 认领一个任务，填写执行者/会话标识、UTC 开始时间、仓库、分支和范围。发现另一会话进行中，先核对其 PR/分支和最后记录；不要仅凭记录过期就同时重做。
5. 用户明确指定的新任务优先，更新当前重点和理由；“继续”则从 `CURRENT.md` 接续。找不到对应任务时在 `TASKS.md` 分配新编号，不复用旧编号。

## 状态与证据

- 任务状态固定为：`待核查`、`待做`、`进行中`、`已验证候选`、`已合并`、`阻塞`、`已有覆盖`、`取消`。文档任务的“已合并”表示已进入其目标默认分支。
- `已合并`和`已有覆盖`默认不重做。只有实际回归、新要求或证据冲突才重新打开，并记录原因。
- 完成条目必须带仓库、固定提交/PR、实际验证范围和未覆盖边界。代码已写、测试通过、PR 已建、PR 已合并、现场有效分别记录。
- 历史测试数是历史报告。未在本轮运行就写“引用历史证据，本轮未复跑”，不能升级成新的通过声明。
- 规划能力不计为已实现；评分不计为经校准的故障概率，预计收益不计为实测收益；当前框架中的阶段定位只是分析判断。
- 保留旧证据和任务历史。遇到摘要与代码冲突，标注冲突并核对；不要静默覆盖他人进度。

## 收尾与中断前

1. 更新 `CURRENT.md`：实际完成、剩余内容、仓库/分支/SHA、PR/检查、阻塞、第一项具体接续动作。注明本地路径是否仅本环境有效。
2. 更新本轮 `TASKS.md` 状态；能力或基线变化时更新 `SUMMARY.md`、`REPOSITORIES.md`；重要取舍追加 `DECISIONS.md`。
3. 在 `logs/YYYY-MM-DD-任务编号-主题.md` 追加一轮记录，使用 `templates/HANDOFF.md`。同日同任务多轮增加时间或序号，不覆盖历史。
4. 校对链接、实际提交和检查结果，提交并推送这些进度文件。写入前重新核对进度仓库 HEAD；并发变更先合并，Git push 不使用强制覆盖。
5. 代码仓库提交与进度仓库提交分别记录。未推送、未合并或 CI 待完成必须保持真实状态。推送受阻时保存本地交接、说明路径及原始错误，最终回复明确“进度未同步”。
6. 只读咨询没有新结论或决策时，无需制造新日志；产生重要结论、重排任务或发现缺口时仍需更新记忆。

在上下文压缩、切换仓库或接近会话结束时，优先保存可接续进度。摘要尽量控制在两分钟可读范围，不把全部日志复制进去。
